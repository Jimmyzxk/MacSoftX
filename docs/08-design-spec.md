# 08 · UI 设计规范 v1（文案 · 命名 · 组件 · 交互）

> 性质：全项目强制契约。任何 UI 改动必须过本规范；代码层对应 `DesignSystem.swift` 唯一 token 入口。
> 背景：迭代 2 复核发现按钮命名、术语、文案规范性不达标（实例见 §7 问题台账）。

## 1. 术语表（全 app 唯一用词，禁止同义词混用）

| 概念 | 唯一用词 | 禁用 |
|------|----------|------|
| GUI 软件 | 应用 | 软件/程序/组件/App |
| 命令行软件 | 命令行 | CLI 工具/命令软件/包 |
| 两类合称 | 软件 | 组件/内容/项目 |
| 包管理器管理的 | ~~受管~~（废弃）→ 用来源徽章本身表达（如「Homebrew」「npm」） | 受管/受控/已管理 |
| 无包管理器管辖 | ~~游离~~（废弃）→ 「手动安装」 | 游离/独立/散装 |
| 品牌名 | UpMac（UI/文档）；代码标识符 `upmac` 不出现在任何 UI | upmac/UPMAC |
| 主窗称呼 | 主窗 | 驾驶舱/控制台/面板 |

## 2. 文案规则

1. **按钮 = 动宾结构，2-4 字**：「立即扫描」「全部更新」「更新」「移除」；禁止纯名词按钮（"重新扫描"→"立即扫描"，全 app 只此一个扫描动词）
2. **状态 = 时态明确**：待更新 / 更新中 / 已更新 / 更新失败 / 需登录 / 需管理员（禁止"成功"单独出现，必须"已更新"）
3. **标题 = 名词短语**：页面名「扫描」「全部软件」「已忽略」「清理」；窗口标题恒为 UpMac
4. **中文标点**：全角标点；句尾不加句号；省略号用「…」仅表进行中（更新中…）
5. **数字与版本**：等宽字体；版本变更固定格式 `2.43.0 → 2.44.0`（旧灰新亮，箭头两侧空格）
6. **禁止营销腔**：统计条直接给数（`7 项待更新 · 覆盖 2 源`），不写"共扫描到…其中…"双句式
7. **错误文案三段式**：源名 + 原因 + 建议（`Homebrew：命令执行超时。可重试或在设置中关闭该源`）

## 3. 组件 token（DesignSystem.swift 唯一出口）

- 颜色语义：主操作=系统蓝（唯一强调色）；错误=系统红；警示=系统橙；成功=系统绿；生态色仅允许出现在 4-6pt 源标记点与图标砖底
- 字体：正文 `.body`；版本号/数字 `.body.monospacedDigit().rounded()`；页面标题 `.title2.bold()`；禁止自造字号
- 圆角：卡片 20 / 胶囊 999 / 图标砖 8（三档，禁止自造）
- 间距：4 的倍数（8/12/16/24）；列表行高 44±8pt
- 按钮层级：主按钮 `.glassProminent`（每视图最多 1 个）；次级 `.glass`；破坏性动作红色文字按钮 + 二次确认
- 可点热区 ≥28pt；对比度按 WCAG AA

## 4. 快捷键表（全局唯一，不得冲突）

⌘R 立即扫描 · ⌘F 搜索 · ⌘1/2/3 切侧栏页 · ⌘, 设置 · Esc 关闭弹层

## 5. 动效规范

- 只用系统原生：symbolEffect（rotate/bounce/pulse）、spring 过渡、contentTransition(.numericText())
- 时长 ≤400ms；`reduceMotion` 时全部直切
- 动效必须有信息量（进度/结果反馈），装饰性动画禁止

## 6. 无障碍

- 图标按钮必须 `accessibilityLabel`；状态不只靠颜色（红字加图标）
- VoiceOver 顺序 = 视觉顺序

## 6.5 交互完整性（2026-09-13 新增，"设置按钮是死的"事故）

- **任何可见控件必须有真实行为**——没有实现的功能，控件一律不出现；必须露出的占位，用 `disabled` + 说明文案（如"即将提供"），禁止可点但无效果
- 主窗/气泡/菜单同一功能多处入口时，行为与文案必须完全一致
- 新增 UI 后自检方式：逐个控件点一遍（维护者验收同样逐个点）

## 6.6 状态诚实性（2026-09-13 新增，"已是最新"伪状态事故）

- **UI 不得声称未验证的状态**：没有真正检测过更新状态的项，一律不显示"已是最新"之类结论
- 清单页只陈述事实（名称/版本/来源/路径）；"待更新"结论只出现在真正跑过检测的源上
- 面向用户的用词禁止工程黑话（受管/游离/源 id 等），用人类语言（"由 Homebrew 管理"→直接显示来源徽章；"手动安装"）

## 7. 现存问题台账（本规范落地时逐项清零）

| 位置 | 现状 | 应改为 |
|------|------|--------|
| 搜索框 placeholder | 「搜索组件名称、类型或源…」 | 「搜索软件名称或来源」 |
| 菜单 vs 气泡 | 「扫描更新」/「重新扫描」两叫法 | 统一「立即扫描」 |
| 菜单 vs 气泡 | 「打开 upmac」/「打开主窗口」 | 统一「打开主窗」 |
| Hero 文案 | 「共扫描到 7 个软件包，其中 7 项待更新」 | 「7 项待更新 · 覆盖 2 源」 |
| 称呼 | 「驾驶舱」残留 | 「主窗」 |
| 更新成功 | 「已更新 (x)」/「更新成功」混用 | 统一「已更新 → 新版本号」 |
| 大小写 | UI 出现 upmac | UI 只出现 UpMac |

## 8. 落地方式

- 新建 `DesignSystem.swift`：颜色/字体/圆角/间距/按钮样式唯一来源，现有视图全部改引 token
- 全量文案审查：逐文件对照 §1-§2 清零，禁止"顺手保留旧写法"
- 新增文案审查单测不现实——以维护者逐屏截图人工验收为准
