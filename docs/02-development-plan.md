# 02 · 开发计划总览

## 1. 开发原则

1. **先引擎后界面**：Provider 采集中枢先行，保证每个迭代都有"机器上可验证"的产出，而不是攒到最后联调
2. **先通知后执行**：先把"看到过期"做可靠，"执行更新"放后——看错是事故，更错更是事故
3. **只做菜单栏 + 一个详情窗**：不做大而全仪表盘，拒绝 scope creep
4. **执行类操作最小权限**：绝不自动 sudo；sudo 项只标注 + 复制命令
5. **真实环境验收**：每个迭代的验收标准都是在本机（真实装的软件）上跑通，不是单测绿就算过

## 2. 里程碑口径

| 里程碑 | 定义 | 落点 |
|--------|------|------|
| **MVP** | 能看（聚合列表）、能选（勾选）、能更（逐项/全部更新成功） | 迭代 4 结束 |
| **v1.0** | 可分发给别人用：公证包、自更新/分发渠道、文档 | 迭代 6 结束 |

总工时估算：**4-6 周业余时间**（人 + 智能体结对开发）。最大变量 = 迭代 3 的 Sparkle 长尾。

## 3. 风险对策

| 风险 | 等级 | 对策 |
|------|------|------|
| Sparkle 版本比较语义各家 app 不一致 | 高 | 统一收敛到 `SUStandardVersionComparator` 行为，全项目唯一比较入口；比较器带完整单测 |
| appcast 失效/超时/格式异常 | 高 | 单项失败不阻塞整体，标"未知"态；超时 5s |
| mas 依赖 App Store 登录态 | 中 | 拿不到就降级只提示，不硬失败 |
| npm -g 需 sudo（取决于 node 装法） | 中 | 探测 prefix 可写性，需 sudo 则标注 |
| launchd + 外置盘 TCC（机器前科） | 中 | 发布版内置盘；自启用 SMAppService |
| GUI 应用"执行更新"无法代办 | 高（已接受） | MVP 只做提示+唤起自更新；cask 装的才代更 |
| 公证流程卡壳 | 低 | 迭代 6 预留整周；备选 brew cask 分发（可免公证分发但体验降级） |
| GPL 传染 | 中（法务） | 引擎全部自研；只参考 topgrade/mpm/Latest 的思路与公开 JSON 接口，不复制代码 |

## 4. License 策略

- 全仓 **MIT**，保持干净可商用
- 红线：不复制 GPL 项目（topgrade、mpm、Latest）的代码；允许看它们调什么命令、解析什么字段（事实性接口）
- MIT 可参考物：TopOff（菜单栏+选择更新模式）、Applite（cask GUI 模式）

## 5. 环境布局（外置盘优先）

```
<项目目录>/     ← 项目本体（含 .build）
<缓存目录>/         ← npm/pip 缓存（已有体系，沿用）
Xcode.app ← 完整版已就位（swift 6.3.3），零内置占用
内置 /Applications/upmac.app         ← 发布版落点（常驻可靠性）
```

构建产物 DerivedData（若引入 Xcode 工程期）显式指到外置盘。

## 6. 质量底线

- 每迭代收尾：`swift build` 零警告 + `swift test` 全绿
- 执行更新前必须有 dry-run 层面确认（列表快照 vs 执行结果 diff 进 history）
- 所有 spawn 的命令走统一执行器：超时、输出捕获、失败分类三件套，禁止散落 `Process()` 调用
